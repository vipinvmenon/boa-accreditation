# Design-fidelity QA pass — 14 Sep 2026

Vipin reported (in another session, 12 Sep, and again today) that several desk
screens still don't match `design/source/boa_design_body.html`. This is the
consolidated findings doc plus a work split for Claude and Cursor to run in
parallel without colliding on the same files.

**Method:** four parallel read-only audits, each comparing one screen's shipped
code line-by-line against its exact `design/source/boa_design_body.html`
range, cross-checked against `docs/DESIGN-SYSTEM.md` (so already-approved
deliberate deviations — the WEB/MOB toggle, the 16px input font floor, the C8
two-colour-layer disagreement — are not re-flagged as bugs). This is the same
method that caught the real, already-fixed bugs recorded in
`docs/CURRENT-STATE.md` (hover states, the toggle colour swap, DeskChrome's
active-nav colour).

**Why this wasn't already caught:** `test:visual` (the automated pixel gate)
has never been able to authenticate an operator in CI, so Control Room, Queue,
Master List and Passes have **never once been pixel-verified** — only Gate,
Vehicle, and (partially) Submission have. `docs/CURRENT-STATE.md` already says
this plainly; this audit is the code-level substitute for the pixel check that
still doesn't run.

## Open — assign to Cursor (`app/desk/queue/queue-screen.tsx`, `lib/schemas/queue.ts`)

This is deliberately the file Claude is *not* touching right now, so Cursor
can start immediately with zero merge risk. **Do pull latest `main` first** —
the Master List fix above touches `app/responsive.css`'s `.d-master-cols`
block; this work should add new selectors after it, not near it.

10 findings, all against `design/source/boa_design_body.html:155-213`:

1. **H1 hardcoded & non-responsive** — `queue-screen.tsx:170` has
   `fontSize:'clamp(42px,7vw,68px)'` for every viewport. Design's `h1b`
   (source line 818) is `34px` mobile / `clamp(38px,4.4vw,58px)` desktop.
   `app/responsive.css` already has a `.d-h1` class with exactly this split —
   use it (see `control-room-screen.tsx` for the reference usage) instead of
   adding a new one.
2. **Section padding hardcoded & non-responsive** — `queue-screen.tsx:166`
   has `padding:'42px 18px 24px'`. Design's `padSec` (source line 845) is
   `28px 18px` mobile / `40px` desktop. Use the existing `.d-pad-sec` class.
3. **Filter-tab padding wrong** — design line 165 specifies `padding:13px
   18px`; shipped filter buttons (`queue-screen.tsx:184`) reuse a generic
   `buttonStyle` with `padding:'10px 16px'`. Give the filter nav its own
   padding.
4. **Filter-tab inactive text colour wrong** — design's inactive `f.fg` is
   `ink3`; shipped uses `var(--ink2,...)`. Swap to `--ink3`.
5. **Filter count badge typography missing** — design line 165: the count
   span is `font-size:11px; font-weight:700; opacity:0.65`. Shipped
   (`queue-screen.tsx:186`) only sets `opacity:0.65`. Add the missing
   `fontSize`/`fontWeight`.
6. **Fourth filter tab changed from "AAA flagged" to "All"** — see "Decisions
   needed" #2 above. Default: revert `QUEUE_FILTERS` in `lib/schemas/queue.ts`
   to match the design unless Vipin says otherwise.
7. **Row grid columns wrong & non-responsive** — `queue-screen.tsx:223`
   hardcodes one grid-template-columns value for every viewport. Design's
   `qCols` (source line 819) is `auto minmax(0,1fr)` mobile / `auto
   minmax(0,2.2fr) 1.5fr auto` desktop — a real mobile collapse to 2 columns
   that's currently missing entirely. Needs a new responsive class in
   `app/responsive.css` (e.g. `.d-queue-cols`) — add it as a new selector,
   don't touch `.d-master-cols`.
8. **Org-level "Reject" bulk button missing** — design (lines 185-188) has
   both "Reject" (outline→bad on hover) and "Approve all →" in the org
   header. Shipped org header (`queue-screen.tsx:211-217`) only has "Approve
   all →" — the bulk reject-a-whole-org control doesn't exist at all. This is
   the biggest functional gap in this list — check `app/hover.css` for the
   existing `hov-*` recipe classes (per-row buttons already use
   `hov-fill-bad` per the audit) before adding new CSS.
9. **Type-colour swatch missing on every row** — design line 199: an
   `8×18px` span filled with `{{ p.typeColour }}` next to the type label.
   No equivalent element exists in the row rendering
   (`queue-screen.tsx:229-235`) — type is currently text-colour only.
10. **Footer summary strip missing entirely** — design (lines 207-210) has a
    bottom bar: "`{n}` approved" / "N pending" / "N rejected" / "Next org: …
    →". Nothing renders this in `queue-screen.tsx` at all. The counts are
    already in component state (`counts`) — this is available data, not
    blocked on anything.

**Not flagged (already correct, don't touch):** the three `style-hover`
